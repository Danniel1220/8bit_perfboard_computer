3. Hard constraints

These must never be violated in a final candidate:

every component remains on the perfboard grid
IC bodies cannot overlap
connector bodies cannot overlap other components
every required electrical connection must eventually be connected
no illegal wire overlaps
only allowed right-angle crossings
active top-side signal pins retain their exclusive two-cell pin-escape area
unused pins do not require escape reservations
power, ground, and fixed constant ties may use underside routing according to the current rules
current pin-clearance and body-clearance rules remain enforced
preserve all electrical logic behavior

Never call a candidate complete unless all hard constraints pass.

4. Optimization priorities

Rank candidates primarily by:

pin-exit readability / pin-clearance validity
visual submodule organization
total wire length
number of bends
routing congestion
symmetry / repeated structure where appropriate

Electrical correctness and hard physical constraints always outrank aesthetics.

However, once candidates are electrically valid, visual organization should carry substantial weight.

5. Visual organization and submodule structure

This is very important.

I do not want a merely electrically valid layout that looks like a random jumper-wire jungle.

The finished board should visually read as a small number of coherent functional submodules that deliberately converge into the final result.

Add explicit functional groups to the configuration. For this ALU, appropriate groups include roughly:

A/B input conditioning / subtraction XOR stage
arithmetic block
logic-operation block
result-selection mux block
output/bus interface
flag-generation block
flag register and flag selector

Strongly reward:

ICs belonging to the same functional group being physically clustered
repeated low/high-nibble structures being aligned or mirrored where practical
keeping related signal wiring mostly inside its own group
clear routing corridors between submodules
deliberate convergence from operation blocks into result selection
connectors being near the subsystem they serve
visually obvious dataflow

Strongly penalize:

unrelated wires wandering through the middle of another functional group
long board-wide routes with no structural reason
dense tangles between unrelated subsystems
routes that obscure the visual relationship between nearby ICs

A slightly longer route that preserves clear submodule structure is preferable to a shorter route that turns the board into spaghetti.

Make these aesthetic weights configurable so I can later tune how strongly grouping and visual structure are preferred.

6. Search architecture

Use an approach suited to long-running heuristic optimization rather than exhaustive enumeration.

A reasonable architecture would be:

route affected nets
validate
score candidate
retain good candidates
periodically perform larger mutations or stochastic restarts
share or checkpoint the global best

Use a sensible default worker count for an 8-core / 16-thread Ryzen 7 5800X3D, but make it configurable.

Profile before optimizing. If the hot loops are limited by pure Python overhead, consider NumPy, Numba, compact arrays, precomputed neighbor tables, bitmasks, or multiprocessing where useful.
